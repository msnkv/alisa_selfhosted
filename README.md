# Алиса — домашний голосовой ассистент

Ассистент отвечает по личным Markdown-файлам из `data/`, общим знаниям
и результатам веб-поиска. Основной сервер использует faster-whisper
для распознавания речи, DeepSeek для ответов и Silero для озвучки.
К серверу можно обращаться с ПК, спутника, из браузера и через Telegram.

Текущее состояние: прототип на ПК завершён, основные доработки этапа 2
реализованы. Home Assistant и собственное устройство — следующие этапы.
Подробные решения и ограничения описаны в [CLAUDE.md](CLAUDE.md),
история изменений — в [JOURNAL.md](JOURNAL.md).

## Telegram-бот

Добавлен отдельный клиент сервера: отправляешь боту **текст или голосовое
сообщение**, а он возвращает **текст ответа и отдельный войс**.
Распознавание и генерация ответа выполняются на существующем сервере.

Что добавлено и изменено:

- `assistant/telegram_bot.py` — получение сообщений через long polling,
  передача вопросов на `/ask`, доставка текста и голоса обратно в Telegram.
  Доступ разрешён одному пользователю по Telegram ID и только в личном чате.
- `assistant/server.py` — входящему OGG/Opus назначается расширение `.ogg`.
  Бот передаёт голосовые без предварительного перекодирования.
- Ответный WAV преобразуется в OGG/Opus через PyAV, чтобы отправить его
  настоящим голосовым сообщением. Отдельная установка FFmpeg не нужна.
- `requirements-telegram.txt` — три зависимости для отдельной установки
  бота: PyYAML, python-dotenv и PyAV. Модели, CUDA и микрофон ему не нужны.
- `.env.example` — шаблоны `TELEGRAM_BOT_TOKEN` и
  `TELEGRAM_ALLOWED_USER_ID`; `config.local.yaml.example` дополнен
  пояснением об адресе и токене сервера для бота.
- `tests/test_telegram_bot.py` — 13 проверок HTTP-обмена, аудиоконвертации,
  доступа, длинных ответов, ошибок и polling.
- [TELEGRAM.md](TELEGRAM.md) — подробная инструкция настройки и запуска.
  Статус и решения также записаны в `CLAUDE.md` и `JOURNAL.md`.

## Быстрый запуск бота

1. Создай бота через [@BotFather](https://t.me/BotFather), команда `/newbot`.
   Добавь в `.env` в корне проекта:

   ```dotenv
   TELEGRAM_BOT_TOKEN=токен_от_BotFather
   TELEGRAM_ALLOWED_USER_ID=
   ```

2. Укажи адрес Алисы в `config.local.yaml` рядом с `config.yaml`:

   ```yaml
   server:
     url: "192.168.31.35:8765"
     # token: "токен сервера, если включён"
   ```

   Адрес взят из примера конфигурации; замени его, если у сервера другой IP.
   Бот читает `server.url` из общих настроек с перекрытием локальным файлом.
   Если адрес не задан, используется `localhost:8765`.

3. Установи зависимости и запусти бота из корня проекта.
   На Windows:

   ```powershell
   py -3.10 -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements-telegram.txt
   .venv\Scripts\python.exe -m assistant.telegram_bot
   ```

   На macOS/Linux:

   ```sh
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements-telegram.txt
   .venv/bin/python -m assistant.telegram_bot
   ```

   Если `.venv` уже существует, используй его без повторного создания.

4. Напиши боту `/start`, впиши показанный ID в `TELEGRAM_ALLOWED_USER_ID`
   в `.env` и перезапусти бота. До настройки ID вопросы к Алисе закрыты.

Сервер на ПК с моделями запускается отдельно: `alisa.bat --serve`.
Машина бота должна видеть адрес сервера и иметь доступ к Telegram.
Для long polling не нужны публичный адрес и входящие порты.

## Раздельные сессии разговоров

Telegram, браузер и спутник передают серверу свой `X-Session-ID`.
История реплик, режим сказок и команда «забудь» действуют только внутри
этого разговора. Распознавание, синтез, личные файлы и инструменты общие.

| Клиент | Как выбирается разговор |
| --- | --- |
| Telegram | `telegram:<chat_id>` — один разговор для текста и войсов в чате |
| Браузер | `browser:<случайный ID>` — сохраняется в localStorage этого браузера и адреса сайта |
| Спутник | Новый `satellite:<ID>` при запуске; можно задать постоянный `server.session_id` |
| Старый клиент без заголовка | Отдельная совместимая сессия `legacy` |

Чтобы спутник продолжал тот же разговор после своего перезапуска,
добавь в его `config.local.yaml`:

```yaml
server:
  session_id: "satellite:kitchen"
```

Каждому спутнику нужен свой ID. Для применения обнови сервер, Telegram-бота
и спутник, перезапусти их и перезагрузи страницу браузера. Обновлённые
клиенты разделяются автоматически. Старые клиенты без заголовка продолжают
делить `legacy`, поэтому их тоже нужно обновить.

Сессии хранятся в памяти сервера: после его перезапуска разговоры начинаются
заново. Сессия удаляется после суток без обращений; хранятся до 128 сессий,
при превышении удаляется самая давно использованная. Журнал остаётся
на диске и дополнен полем `session_id`; старые поля сохранены.
ID сессии не заменяет авторизацию: при включённом `server.token`
по-прежнему требуется `X-Token`.

## Потоковый ответ и остановка

Спутник и браузер получают готовые фразы через `/ask-stream` и начинают
проигрывать их по очереди. В режиме сказки первая фраза передаётся ещё
во время генерации продолжения. Обычный ответ разрешается после завершения
финального шага модели: текст, сказанный перед вызовом инструмента,
в озвучку не попадает. Сервер не собирает весь звук сказки в один WAV;
очередь спутника ограничена двумя событиями плюс текущая фраза.

- **Браузер:** кнопка **«Стоп»** обрывает текущий звук и запрос.
- **Спутник:** **Ctrl+C во время ответа или ожидания ответа** отменяет
  текущую реплику и возвращает к ожиданию нового вопроса. Ctrl+C вне
  ответа по-прежнему завершает клиент.
- Отмена относится к конкретному запросу и сессии. Она не сбрасывает
  историю и не останавливает ответы другим клиентам.
- Заглушки спутника прекращаются с первым звуком ответа. Фраза про поиск
  выбирается по событию сервера, поэтому сказка больше не сопровождается
  ложным «ищу» во время ожидания.

Для применения обнови и перезапусти сервер и спутник, перезагрузи страницу.
Старый `/ask` сохраняется: Telegram получает
полный ответ текстом и одним войсом, как раньше.

### Голосовое «стоп» на спутнике

Во время ответа скажи отдельное **«стоп»**, без кодовой фразы. Спутник
останавливает динамик и отменяет текущий запрос на сервере, затем снова
ждёт вопроса. Работает в режимах с микрофоном; Ctrl+C остаётся доступным.

Обнови зависимости спутника и перезапусти его:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-client.txt
```

Добавлен `pywebrtc-audio==0.2.0` с WebRTC AEC. Один двусторонний аудиопоток
48 кГц одновременно читает микрофон и воспроизводит ответ; точные отсчёты
выхода служат эталоном для подавления эха. Vosk сначала ищет кандидата,
затем обычным словарём подтверждает отдельное слово на коротком **очищенном**
фрагменте. Модель переиспользуется от wake word либо загружается при первом
ответе. Запись микрофона для этой функции остаётся в памяти спутника.
Описание библиотеки: [pywebrtc-audio](https://github.com/strands-labs/pywebrtc-audio).

Защита от собственного голоса:

- Первые 0,8 секунды звучащей речи отведены на адаптацию AEC.
- Если текст озвучиваемой фразы содержит слово «стоп», распознавание
  закрыто на всю эту фразу и ещё 0,5 секунды после неё с учётом задержки
  динамика. В этот короткий период пользовательский «стоп» тоже не сработает.
- Ошибка AEC, пропуск аудиокадров или переполнение очереди отключают
  голосовую отмену до следующего ответа. Сырой микрофон вместо AEC не используется.

Настройки в `config.local.yaml` (эти значения уже действуют по умолчанию):

```yaml
voice_stop:
  enabled: true
  min_confidence: 0.9  # допустимо 0.8–1.0
  echo_delay_ms: 0    # автоматическая оценка; ручная настройка после проверки
```

Нужны микрофон и выход, поддерживающие одновременную работу на 48 кГц.
При несовместимых устройствах клиент сообщает о недоступности голосового
стопа и оставляет ручную отмену. Слишком тихая или заглушённая динамиком
команда может быть пропущена: повтори её ближе к микрофону либо нажми Ctrl+C.
Безошибочность в любой комнате не гарантируется. На синтетическом речевом
прогоне с сильным эхом подтверждены 2 из 3 команд поверх рассказа, ложных
остановок на собственном голосе и контрольных фразах не было.
Проверка живого микрофона и динамика на целевом Windows-спутнике ещё нужна.

Текущая фраза на клиенте обрывается сразу при ручной остановке. Сервер
проверяет отмену при ожидании моделей, между фрагментами API, перед/после
синтеза и при отправке в сеть. Уже выполняющийся вызов распознавания,
синтеза, поиска или ожидание данных от API заканчивается либо достигает
своего таймаута, после чего генерация прекращается. При отмене до
завершения `Assistant.ask` частичный ответ не записывается в память.
Если модель уже закончила, полный ответ может оставаться в истории,
даже когда клиент остановил его воспроизведение.

## Проверка и ограничения

После установки зависимостей бота:

```sh
python -m unittest discover -s tests -p test_telegram_bot.py -v
```

Набор Telegram-клиента: **13 из 13 проверок прошли**. Тесты используют
HTTP-подмены Telegram и Алисы, реально передают аудио и проверяют
декодирование ответного Opus. Живой обмен с Telegram и моделями
пока не проверен: нужны токен бота и работающий сервер.

Для полной проверки в окружении с зависимостями серверной части,
спутника и `requirements-telegram.txt`:

```sh
python -m unittest discover -s tests -p 'test_*.py' -v
```

Проверки включают разделение сессий, передачу первой фразы до завершения
генерации, отбрасывание текста шагов с инструментами, остановку ответа
и освобождение моделей при медленном клиенте. JavaScript браузера
проверяется на дроблении NDJSON, последовательном воспроизведении и
кнопке «Стоп».
Для голосового стопа проверяются эталон динамика, отказ AEC, защита фраз
со словом «стоп», переполнение очереди, подтверждение команды и отмена
HTTP-запроса. Тест настоящего WebRTC требует `pywebrtc-audio`.
Речевые проверки `tests/test_voice_stop_speech.py` используют настоящие
AEC/Vosk и локальные WAV; без модели и записей они явно пропускаются.
Как воспроизвести записи без доступа к устройствам — в начале этого файла
тестов. Это синтетическая проверка, она не заменяет проверку в комнате.
Итоговый локальный прогон: **70 из 70 проверок прошли, без пропусков**.

Сетевые проверки используют настоящий локальный HTTP-сервер и настоящую
логику памяти, подменяя ответы API, распознавание и синтез. Проверка
JavaScript страницы дополнительно использует Node.js и пропускается,
если он не установлен; для работы самой Алисы Node.js не нужен.

В Telegram длинный ответ приходит одним войсом после генерации и синтеза.
Голосовые заметки и напоминания этим изменением не добавлены.

Секреты, личные файлы, модели и настройки конкретной машины
хранятся локально и исключены из Git. Содержимое `data/` отправляется
в API DeepSeek при формировании ответа.
