# Напоминания с доставкой в Telegram

Пример разговора через спутник, браузер или Telegram:

> — Напомни завтра в семь поставить тесто.
> — В семь утра или вечера? Ничего не сохранено.
> — Утра.
> — Напомнить 24.10.2026 в 07:00:00 (Europe/Moscow, UTC+03:00): поставить тесто.
>   Сохранить? Скажи «подтверждаю» или «отмена». Пока не сохранено.
> — Подтверждаю.
> — Напоминание сохранено. Доставка в Telegram.

Дата в примере предполагает, что разговор состоялся 23 октября 2026 года.
В работе «завтра» и «через два часа» вычисляются моделью относительно
текущего времени **службы напоминаний** в её часовом поясе. Код проверяет
дату и формирует точный предпросмотр. Прошедшее время, пропущенный или
двойной час при переводе часов отклоняются. Ошибку разбора моделью можно
заметить до сохранения: проверь дату, время, пояс и текст.

Подтверждение принимает код, а не модель. Оно действует десять минут и
только в том же разговоре. Достаточно отдельного «да», «подтверждаю» или
«сохрани». «Отмена» отклоняет заявку. Для изменения повтори полную просьбу
с правильным временем; после нового предпросмотра снова подтверди.
Несвязанная реплика, «забудь» и перезапуск основного сервера сбрасывают
неподтверждённую заявку. Отмена, замеченная сервером до завершения
предпросмотра, тоже её сбрасывает. Остановка уже переданного звука
не равнозначна отказу от заявки: скажи «отмена». Заявка не записывается
в SQLite. Уже сохранённые напоминания от этого не удаляются.

## Где работает планировщик

`python -m assistant.reminders` — отдельная лёгкая служба без моделей,
CUDA, звука, DeepSeek и polling Telegram. Запускай её на постоянно
включённой машине: например, домашнем Linux-сервере или VDS, доступном
ПК Алисы через частную сеть/VPN. Можно поставить рядом с Telegram-ботом.
Служба использует того же бота только для отправки сообщений, поэтому
вторая копия `getUpdates` не появляется. Рабочий ПК Алисы нужен для
создания заявки и подтверждения; для доставки сохранённых напоминаний
он может быть выключен. Сам планировщик и интернет должны работать.

Служба хранит SQLite **на собственном локальном диске**, а не на сетевой
папке ПК Алисы. При простое службы напоминания сохраняются; после запуска
просроченные отправляются сразу. Проверка очереди — каждые две секунды.

## Настройка службы

1. Скопируй проект на постоянно включённую машину. Нужен Python 3.10+.
   Установи лёгкое окружение:

   ```sh
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements-reminders.txt
   ```

   На Windows команды аналогичны через `.venv\Scripts\python.exe`.
   `tzdata` обеспечивает часовые пояса в том числе там, где нет системной
   базы IANA; это штатный механизм [Python zoneinfo](https://docs.python.org/3/library/zoneinfo.html).

2. На машине службы укажи в `.env`:

   ```dotenv
   TELEGRAM_BOT_TOKEN=токен_от_BotFather
   TELEGRAM_ALLOWED_USER_ID=твой_числовой_Telegram_ID
   REMINDERS_TOKEN=общий_случайный_секрет
   ```

   Секрет можно создать командой:

   ```sh
   python3 -c "import secrets; print(secrets.token_hex(32))"
   ```

   До первой доставки отправь этому боту `/start` со своего аккаунта
   и убедись, что бот не заблокирован. Свой ID можно узнать через `/start`
   при работающем Telegram-клиенте Алисы, если доступ ещё не настроен.
   Доставка использует обычный
   [Telegram sendMessage](https://core.telegram.org/bots/api#sendmessage).
   ID получателя задаётся оператором службы и сохраняется с напоминанием;
   модель и HTTP-клиент не могут выбрать другого получателя.

3. В `config.local.yaml` **на машине службы**:

   ```yaml
   reminders:
     host: "0.0.0.0"  # либо конкретный адрес домашней сети/VPN
     port: 8766
     timezone: "Europe/Moscow"
     database: "state/reminders.sqlite3"
   ```

   Без переопределения служба слушает только `127.0.0.1:8766`.
   Относительный путь базы считается от корня проекта. Папка `state/`
   исключена из Git. Все запросы, включая список и health, требуют секрет.
   HTTP предназначен для доверенной домашней сети/VPN; не публикуй этот
   порт в открытом интернете. Через внешнюю сеть нужен HTTPS-прокси.

4. Запусти из корня проекта:

   ```sh
   .venv/bin/python -m assistant.reminders
   ```

## Подключение ПК Алисы

На ПК с моделями обнови основные зависимости (`requirements.txt`),
впиши тот же `REMINDERS_TOKEN` в `.env`, а в `config.local.yaml`:

```yaml
reminders:
  url: "http://192.168.31.50:8766"
```

Замени адрес адресом машины службы. Если оба процесса на одной машине,
используй `http://127.0.0.1:8766`. Перезапусти сервер Алисы или локальный
голосовой процесс. На спутнике и в отдельном Telegram-клиенте секрет
службы не нужен: их вопросы обрабатывает основной сервер.

Пустой URL по умолчанию отключает подключение: на просьбу напомнить Алиса
сообщит о настройке, не станет обещать сохранение. При недоступной службе
сохранение также не подтверждается. Если ответ на сохранение потерялся
в сети, повтори «подтверждаю» в пределах десяти минут: используется тот
же ID, второй записи не будет. Позже результат можно проверить списком.

## Список, отмена и доставка

- «Мои напоминания» показывает до 50 ожидающих записей, точное время,
  состояние и полный ID. Список общий для единственного владельца.
- «Отмени напоминание ID» отменяет ожидающую запись. Удобнее скопировать
  команду и ID в Telegram или браузер. Начавшуюся отправку отменить нельзя.
- `pending` — ждёт срока или повторной попытки; `sending` — отправка;
  `failed` — Telegram требует исправления доступа/настроек. После такой
  ошибки повторная проверка происходит через час; исправь токен, ID или
  разблокируй бота. Временные сетевые ошибки повторяются с увеличением
  интервала от минуты до часа. После смены ID владельца старые записи
  не перенаправляются новому человеку: верни прежний ID либо отмени их.

SQLite хранит время в UTC, исходный пояс, получателя, состояние и попытки.
Сохранение по одному ID идемпотентно. Отправки резервируются транзакцией,
поэтому пара работников не заберёт одну запись одновременно. Если процесс
упал во время отправки, резерв истекает через десять минут, затем запись
доступна снова. Telegram не даёт этому вызову идемпотентного ключа:
если сообщение дошло, а ответ потерялся либо процесс упал до записи
результата, повторная доставка **может создать дубль**. Обещания «ровно
один раз» нет. После успешного ответа Telegram запись больше не отправляется.

Поддерживаются разовые напоминания одному владельцу. Доставка текстовая,
без войса. Повторяющиеся расписания и голосовые заметки не добавлены.
Для резервной копии останови службу и скопируй всю папку `state/` вместе
с файлами SQLite/WAL/SHM. База не входит в Git и содержит личные тексты.

## Автозапуск на Linux

Шаблон — `infra/alisa-reminders.service`. Исправь `User`, `WorkingDirectory`
и `ExecStart` под свою машину, сохрани `.env` и `state/` с правом доступа
для этого пользователя. Затем **на машине службы**:

```sh
sudo cp infra/alisa-reminders.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now alisa-reminders
systemctl status alisa-reminders
journalctl -u alisa-reminders -f
```

Это инструкция и шаблон: автоматически служба ни на одну машину не
устанавливалась. На Windows используй Планировщик заданий с запуском
при старте системы, рабочей папкой проекта и аргументами
`-m assistant.reminders` для Python из `.venv`.

## Проверка

```sh
python -m unittest discover -s tests -p 'test_reminders.py' -v
```

Используются временная SQLite, настоящий локальный HTTP и подменённые
DeepSeek/Telegram. Проверяются подтверждение, изоляция сессий, точное время,
перезапуск, дедупликация сохранения, резервирование, повтор доставки,
отмена, авторизация и запуск без тяжёлых пакетов. Настоящих сообщений
в Telegram эти тесты не отправляют. Живую доставку нужно проверить после
настройки службы: создай напоминание на несколько минут вперёд, проверь
предпросмотр, подтверди и дождись сообщения при выключенном основном ПК.
